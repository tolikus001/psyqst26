## 3. ЖЁСТКИЕ ОГРАНИЧЕНИЯ (НЕ НАРУШАТЬ В ТЗ)

> [!CAUTION]
> Эти ограничения технические. Если ТЗ их нарушает — Кодер вернёт ТЗ на доработку.

### 3.1. Авторский текст — ДОСЛОВНО
Кодер **НЕ сокращает**, **НЕ перефразирует**, **НЕ вырезает** авторский текст Анатолия Фёдорова. Весь текст переносится от первого до последнего слова. Кодер лишь разбивает его на визуально-дышащие блоки для удобства чтения с мобильного экрана.

### 3.2. Кодер НЕ придумывает контент
- НЕ придумывает тексты уроков и лендингов
- НЕ проектирует механики интерактивов (вопросы, карточки, баллы)
- НЕ пишет системные промпты для ИИ-Попутчика
- НЕ анализирует ЦА и не профилирует боли
- НЕ генерирует продающие тексты

Всё это — зона ответственности Атланта.

### 3.3. Технические запреты
- ❌ **Нет optional chaining** (`a?.b?.c`) — старые WebView падают с SyntaxError
- ❌ **Нет `100vh` / `h-screen`** — прыгает из-за адресной строки. Используется `100dvh`
- ❌ **Нет `body { position: fixed }`** в iframe-песочницах
- ❌ **Нет внешних картинок** — только инлайн SVG для иконок
- ❌ **Нет `import`/`require` в клиентском коде** — всё в одном HTML-файле
- ❌ **Файл > 150 строк** — аудит блокирует коммит (но для HTML-экранов допускается, это ограничение на вспомогательные JS-файлы)

## 4. ФОРМАТ ТЗ ДЛЯ КОДЕРА

### 4.1. Формат файла
- **Строго `.md`** (Markdown)
- Кодер не парсит `.docx`, `.pdf`, `.txt` надёжно

### 4.2. Именование файла
```
tz_{НН}_{тип}.md
```
Где `{НН}` — номер экрана (двузначный), `{тип}` — тип контента.

**Примеры:**
```
tz_16_lesson1.md         — ТЗ на урок 1 (сценарий 2)
tz_22_bonus1.md          — ТЗ на бонус 1 (сценарий 2)
tz_02_landing_update.md  — точечная правка лендинга
tz_26_lesson6_NEW.md     — ТЗ на НОВЫЙ экран (ещё не существует)
tz_03_lesson1_PATCH.md   — правки к существующему экрану
```

### 4.3. Куда класть
```
/Users/zalina/Documents/docs/coding/миникурс/baza/approved_lessons/
```

### 4.4. Обязательная структура ТЗ (6 разделов)

#### РАЗДЕЛ 1: МЕТАДАННЫЕ (yaml-шапка)

```yaml
---
lesson_number: 16
target_file: "16_lesson1.html"
api_endpoint: "/api/lesson2-1-strategy"
notibot_article_id: "5hR7Av3us4aIKmTZr7b6J2"
scenario: 2
type: "lesson"
next_screen: "17_lesson2.html"
prev_screen: "15_landing_partner_2.html"
has_ai_interactive: true
has_audio: false
has_video: false
---
```

| Поле | Обязательно | Описание |
|---|---|---|
| `lesson_number` | ✅ | Порядковый номер экрана (16, 17, 18...) |
| `target_file` | ✅ | Имя файла в `out/client/` |
| `api_endpoint` | ✅ | Endpoint бэкенда (или `"NONE"` если нет ИИ) |
| `notibot_article_id` | ✅ | ID страницы в Notibot (или `"PENDING"`) |
| `scenario` | ✅ | Номер сценария (1 или 2) |
| `type` | ✅ | `lesson` / `bonus` / `landing` / `quest` |
| `next_screen` | ✅ | Куда ведёт кнопка «Далее» |
| `prev_screen` | ⬜ | Предыдущий экран (для навигации) |
| `has_ai_interactive` | ✅ | Есть ли ИИ-интерактив |
| `has_audio` / `has_video` | ⬜ | Есть ли медиа (если да — положить в media/) |

## 6. МЕДИА-АССЕТЫ

Если новый урок использует **видео, аудио или картинки**:

1. Атлант кладёт файл в:
   ```
   baza/approved_lessons/media/{НН}/
   ```
   Пример: `baza/approved_lessons/media/26/lesson6_intro.mp4`

2. В ТЗ указать:
   ```yaml
   has_video: true
   media_files:
     - name: "lesson6_intro.mp4"
       type: video
       description: "Видеоприветствие к уроку 6"
   ```

3. Кодер перенесёт файл в `out/server/files/` и подключит через `resolveMediaUrl()`.

## 7. ПРОТОКОЛЫ ВЗАИМОДЕЙСТВИЯ

### 7.1. Основной цикл
```
Атлант утверждает контент
    ↓
Сохраняет ТЗ в baza/approved_lessons/tz_XX_type.md
    ↓
Кодер читает ТЗ
    ↓
Собирает экран в out/client/XX_type.html
    ↓
Подключает endpoint в out/server/server.js (если есть ИИ)
    ↓
Запускает аудит: node scripts/audit.js
    ↓
Коммитит результат в Git
    ↓
Обновляет STATUS.md → статус "✅ Собрано"
```

### 7.2. Обратная связь (если ТЗ неполное)

Если Кодер обнаружил проблему в ТЗ, он создаёт:
```
baza/approved_lessons/FEEDBACK_XX.md
```
С описанием:
- Какого раздела не хватает
- Что противоречит (например, «5 шагов в описании, но только 3 карточки»)
- Что нужно уточнить

**Кодер НЕ додумывает недостающее самостоятельно.** Ждёт исправленного ТЗ.

### 7.3. Правки к существующим экранам

Если нужно обновить уже собранный экран:
```
tz_{НН}_{тип}_PATCH.md
```
Содержит **ТОЛЬКО** то, что изменить:
- Какой блок заменить (указать конкретную секцию)
- Новый текст / механику
- Что **НЕ трогать**

### 7.4. Таблица статусов

Файл `baza/approved_lessons/STATUS.md` обновляется после каждой сборки:

```markdown
| Файл ТЗ | Статус | Дата | Целевой файл |
```
